# DrapixAI website compliance audit

Date: 17 October 2026. Status: engineering audit and counsel review draft; **not legal approval or WCAG certification**.

## Scope and evidence boundary

Initial read-only review preceded the technical changes described in the change log. Baseline commit: `1cb769148ef51773bdaaadf0098106cea0375176`, with pre-existing concurrent lower-body edits. Reviewed the public pages, shared components, browser storage and embeds, NextAuth and dashboard/admin cookie boundaries, API route inventory and security middleware, Prisma data model, billing and Shopify integrations, retention implementations, worker spool lifecycle, deployment templates, release controls and existing operational evidence. This is a repository review with targeted tests, not exhaustive line-by-line assurance, a live production inspection, or an independent penetration test.

The business evidenced by code is B2B virtual try-on SaaS for fashion merchants, with a shopper-facing photo upload SDK and public demo. Standard upper-body CatVTON is the release scope. A shipping policy is not indicated for this software service; merchants' own garment sales remain separate. Registration, hosted Stripe billing, optional Google OAuth, email, object storage, database, Redis, merchant webhooks and optional Shopify product synchronization are represented in source. Presence in code does not establish a deployed vendor, signed agreement, enabled integration or processing country.

User confirmation requested for legal entity, address, operating/launch countries, grievance owner, children and approved cancellation/refund policy. These facts remain unverified. Source pricing uses USD displays; Stripe currency/catalog are environment configured. India is the planning assumption from the user's context, not proof of incorporation. See [applicability matrix](applicability-matrix.md), [data and technology inventory](data-inventory.md), [legal review checklist](legal-review-checklist.md), and [verification](verification-report.md).

## Security controls inspected

`server.ts` uses Helmet, bounded parsers, raw signed-webhook paths, explicit CORS and production configuration checks. Password routes use bcrypt, identity/rate limits and verification codes. Separate signed HttpOnly dashboard/admin sessions, production Secure cookies, origin checks and no-store responses are implemented. SDK/v1 have tenant/key scope boundaries, file content validation, remote-fetch controls, capacity control and durable quota admission. Immutable security logs and version-aware storage deletion have regression tests. These are implementation observations, not a claim of ASVS certification or absence of exploitable defects. Test and deployment gaps remain in the risk register.

Public launch remains **not approved**. The original 22 gates and the stricter four-request requirement are not waived by this audit.
